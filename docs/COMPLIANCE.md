# Official-rules audit — October 17, 2026 IST

Sources: [event rules](https://www.wemakedevs.org/hackathons/falkordb/rules),
[schedule](https://www.wemakedevs.org/hackathons/falkordb/schedule), and
[Code of Conduct](https://www.wemakedevs.org/coc). This is a preparation audit,
not organizer approval. The signed-in registration/submission form may have
additional required fields; those are not assumed complete.

| Rules | Evidence and remaining responsibility |
|---|---|
| 1: solo/up to four, one team per participant | Solo is the planned format. Participant must verify registration/team membership. |
| 2–3: FalkorDB primary and essential | Native dependency, policy and memory queries; graph outages stop live operations. Real integration tests run in GitHub Actions. |
| 4: hosting/language choice | Python/React; FalkorDB Docker or Cloud. |
| 5: name entered tracks | Primary: Agents That Act on Connected Data. Participant must make the final form selection; additional tracks are optional. |
| 6: permitted data | All operational fixtures are synthetic. No private production records are loaded. |
| 7–8: event window and new work | Planning is separated in PRE_EVENT_NOTES.md. Recorded implementation is within the event. Participant must truthfully represent originality and dates. |
| 9: reused tools and original work | Dependencies are declared; no other project's application is copied. Original contribution must be explained honestly. |
| 10: submission materials | Public repository, README/local instructions, graph model and actual Cypher are committed. Check submission.json and the demo directory for current video/artifact status. |
| 11: AI disclosure | Explicit README disclosure covers generated code, tests, styling and documentation. |
| 12–13: understanding/contribution | Not automatically verified. Use CONTRIBUTOR_GUIDE.md, run the setup, inspect the queries, make and record meaningful personal contributions. |
| 14: track prizes | No award or ranking is claimed. |
| 15: ownership | Participant/team owns its original work; third-party dependencies retain their licenses. |
| 16–18: conduct/enforcement | Ongoing participant obligations. No plagiarism, harassment or judging manipulation. |

The mandatory video must show actual project behavior. A replay of measured agent
output is labeled as recorded; a fixture preview is never claimed as a live run.
A static replay showcase is not a deployed live backend. Local instructions are
the full-application hosting alternative. Scores describe a small synthetic
benchmark and are not claims of general superiority.

Submission closes October 18, 2026 at 11:59 PM IST. Registration, review and the
final submission itself are participant-owned and remain pending until verified.
